Visão geral

Os PDFs ficam no servidor; o Supabase fornece autenticação e banco de dados. A integração com WhatsApp é opcional.

0

Antes de começar

Tenha os acessos e dados necessários à mão.

ServidorUmbrel OS com Portainer instalado e conectado ao Docker local.
Contas e dadosSupabase, e-mail do administrador e endereço público do portal.

Não coloque arquivos de ambiente no Git. A chave SUPABASE_SERVICE_ROLE_KEY dá acesso administrativo ao banco; mantenha-a somente no servidor.

1

Prepare o Supabase

Crie o banco e aplique as tabelas e regras de acesso.

  1. Crie um projeto no painel Supabase.
  2. Abra SQL Editor e execute o conteúdo de supabase-schema.sql deste repositório.
  3. Em Project Settings → API, copie a Project URL, a chave pública anon e a chave secreta service role.

Confira: as tabelas magazines, settings e logs_whatsapp aparecem no Table Editor.

A chave service role nunca deve ir para o navegador ou para o Git. Guarde-a somente no arquivo de ambiente do servidor.

2

Crie a conta administradora

O painel exige o papel seguro app_metadata.role.

  1. Em Authentication → Users, crie um usuário com e-mail e senha.
  2. Copie o UUID do usuário.
  3. Em um ambiente confiável no servidor, use a Admin API do Supabase para atribuir app_metadata.role = "admin" ao UUID.
  4. Saia da sessão e entre novamente para receber as permissões atualizadas.
Admin API · exemplo servidor
await supabase.auth.admin.updateUserById("UUID-DO-USUARIO", {
  app_metadata: { role: "admin" }
});

Faça essa chamada somente no servidor, com a service role. Não use user_metadata para conceder acesso: o próprio usuário pode alterá-lo. Referência oficial da Admin API ↗

3

Prepare o ambiente da Stack

Cadastre os valores no Portainer; não publique um arquivo .env no Git.

Antes de abrir o Portainer, gere uma chave longa para WHATSAPP_API_KEY. Gere também CRON_SECRET se for chamar a rota de cron por um serviço externo. Mantenha as chaves em um gerenciador de senhas.

Gerar segredo no seu computador (opcional)
openssl rand -hex 32

Na etapa de criação da Stack, abra Environment variables e adicione as variáveis abaixo como pares nome/valor. As duas chaves NEXT_PUBLIC_* também são passadas ao build para serem incluídas no app do navegador:

Supabase — obrigatóriasNEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
Portal — obrigatóriasNEXT_PUBLIC_APP_URL (URL pública real)
APP_HOST_PORT (padrão 3001)
CRON_SECRET (opcional; cron externo)
WhatsApp — EvolutionWHATSAPP_PROVIDER=evolution
WHATSAPP_API_URL=http://evolution-api:8080
WHATSAPP_API_KEY (segredo gerado)
WHATSAPP_INSTANCE=pib-cataguases-ebd
WhatsApp — opcionaisWHATSAPP_GROUP_JID=ID_DO_GRUPO@g.us
WHATSAPP_DEFAULT_MESSAGE
WHATSAPP_EVOLUTION_PUBLIC_URL
WHATSAPP_HOST_PORT (padrão 8081)

Defina as três chaves Supabase, NEXT_PUBLIC_APP_URL e WHATSAPP_API_KEY. O CRON_SECRET é opcional: sem ele, a rota de cron aceita somente sessão autenticada de administrador; com ele, também aceita chamadas externas com Bearer token. Restrinja o acesso administrativo ao Portainer, pois as variáveis da Stack incluem credenciais sensíveis.

Para um repositório privado, use a opção de autenticação do Git com um token de acesso pessoal que tenha somente leitura do repositório.

4

Implante pelo Portainer

Crie a Stack diretamente do repositório Git.

  1. No Umbrel, abra Portainer e selecione o ambiente Docker local.
  2. No menu lateral, abra Stacks → Add stack e use o nome ebd-revista-manager.
  3. Em Build method, escolha Repository.
  4. Preencha Repository URL com a URL Git do projeto; em Repository reference, selecione a branch que contém as alterações que deseja implantar (por exemplo, main).
  5. Em Compose path, informe docker-compose.yml (está na raiz deste repositório).
  6. Se aparecer a opção, adicione as variáveis da etapa anterior em Environment variables.
  7. Revise os valores e clique em Deploy the stack. O Portainer clona o repositório, constrói a imagem e inicia os serviços.

Deixe atualizações automáticas desligadas até validar a primeira implantação. Para atualizar depois de enviar mudanças ao Git, abra a Stack e use Pull and redeploy (ou a opção equivalente da sua versão do Portainer).

Confira a página da Stack: os serviços ebd-app e evolution-api devem estar em execução. Abra os logs de ebd-app pelo Portainer para investigar erros.

Abra http://umbrel.local:3001. O painel administrativo fica em /admin/login.

Os PDFs usam o bind mount ./data/uploads definido no Compose. Faça cópias de segurança dessa pasta antes de atualizar/recriar a Stack e confirme que os uploads continuam no volume local após a primeira implantação. A Evolution API não deve ser exposta diretamente à internet. Se a porta local 8081 também estiver ocupada, defina WHATSAPP_HOST_PORT com outra porta livre no Portainer. Acesse o portal pela porta configurada; neste Umbrel, a porta 3000 já pertence a outro app.

Ver documentação oficial: adicionar uma Stack pelo Git ↗

5

Conecte o WhatsApp (opcional)

Crie uma instância e faça o pareamento pelo QR Code.

Primeiro, abra um túnel SSH no computador e mantenha essa janela aberta:

Terminal local
ssh -L 8081:127.0.0.1:8081 umbrel@umbrel.local

Com o túnel ativo, envie o pedido do seu computador usando a chave definida nas variáveis da Stack:

Terminal do computador · túnel ativo
curl -X POST http://localhost:8081/instance/create \
  -H "apikey: SUA_WHATSAPP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"instanceName":"pib-cataguases-ebd","token":"SUA_WHATSAPP_API_KEY","qrcode":true}'

Com o túnel ativo, abra localhost:8081/instance/connect/pib-cataguases-ebd e leia o QR com o celular da igreja.

No painel, abra Configurações, informe o JID e use Testar conexão. Revise destinatário e mensagem antes de habilitar disparos automáticos.

6

Faça a primeira publicação

Confirme cada parte do fluxo antes de divulgar o portal.

  • Entre com o usuário administrador em /admin/login depois que os serviços da Stack estiverem ativos.
  • Envie um PDF válido de até 25 MB em Nova Revista.
  • Confira título, data da lição e horário de publicação.
  • Teste a visualização e o download no portal público.
  • Habilite WhatsApp só depois de validar grupo e mensagem.

Ajuda rápida

O login não abre o painel

Confirme que o usuário recebeu app_metadata.role = admin e entre novamente para renovar a sessão.

O Supabase não conecta

Revise as variáveis no Portainer em Stacks → sua Stack → Editor/Environment variables e redeploy a Stack.

O QR Code não abre

Mantenha o túnel SSH ativo e confirme em Portainer → Stacks que evolution-api está em execução.

O upload falha

Confira espaço em disco, o limite de 25 MB para PDF e os logs do app.

Como atualizar?

Faça backup da pasta data/uploads; envie as alterações ao Git e use Pull and redeploy na Stack.
